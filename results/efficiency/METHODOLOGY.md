# MMCL 参数量与效率统计规范

## 参数量统计

参数表应拆分不同含义的量，不应将它们合并成一个含糊的 `Params`：

1. **峰值更新参数量（Peak updated parameters）**：在全部增量任务和训练阶段中，
   任一优化器更新前实际具有非空梯度的唯一参数元素数量峰值。该指标可以正确处理
   多阶段训练以及参数冻结/解冻。
2. **最终额外学习参数量（Final extra learned parameters）**：相对一份共同冻结的
   OpenCLIP，在最小最终推理导出中仍需保留的全部方法特有学习参数，包括分类头。
   如果学习权重替换了相同形状的基线权重，则其最终净额外参数为 0，但训练时仍计入
   峰值更新参数量。
3. **额外冻结参数量（Additional frozen copies）**：共同 backbone 之外的冻结编码器
   或模型副本。这些参数虽然不参与训练，但会占用部署存储并可能产生额外计算。
   本实现中的完整 OpenCLIP 为 149.620737M 参数；L2P/DualPrompt 使用的额外
   ViT-B/16 视觉查询编码器为 86.192640M 参数。
4. **辅助状态（Auxiliary state）**：持续保留的原型、类别均值、协方差、特征统计和
   历史张量。按照实际 dtype 统计字节数并以 MiB 报告，不计入学习参数量。
5. **随类别数与任务数的增长关系**：同时报告相对类别数 `C` 和任务数 `T` 的复杂度，
   避免单个最终数值掩盖持续学习方法的可扩展性。

增长式中，`D=512` 为 CLIP 嵌入维度，`V=768` 为视觉投影前维度，`p=10`
为本配置中 CLG-CBM 每类保留的概念数量。

只有当重参数化导出确实替换原权重且已验证数值等价时，才能按照净额外参数统计。
因此，BOFA 在融合投影后可以报告 0 个净额外 backbone 投影参数，但不能写成 0 个
训练参数或 0 个方法状态。

ENGINE 的构造函数还在 `BaseNet.convnet` 元组中保留了一份未注册的完整
149.620737M OpenCLIP。代码检查表明该副本未被 ENGINE 前向路径使用，因此将其列为
可裁剪的实现冗余，并从算法辅助状态中扣除；部署导出时应删除该副本。

## 时间与显存统计

- 硬件：`comput1` 节点上的 NVIDIA A800 80GB PCIe，使用物理 GPU 0/1/2。
- Backbone：OpenCLIP ViT-B/16，LAION-400M 权重。
- 随机种子：1993。每个“方法 × 数据集”执行 3 次完整独立运行。
- 训练时间：十个任务 `incremental_train` 的 CUDA 同步墙钟时间之和。排除模型与
  checkpoint 加载、任务级评测和仅用于日志的 epoch 测试；保留算法必需的特征提取、
  统计量、伪样本生成和模型选择。训练采用各方法原始配置的 batch size 与 epoch 日程。
- 推理时间：最终 100 类完整测试集的 `_eval_cnn` 端到端路径。所有方法统一使用
  batch size 64 和 8 个 data-loader workers。正常最终评测作为预热，随后运行 3 次完整
  推理并取中位数，作为该次独立运行的推理观测值。
- GPU 显存：使用进程内 `torch.cuda.max_memory_allocated`。在每个训练任务或推理重复
  前重置峰值。原始 JSON 保留峰值 reserved memory 供诊断，但不作为主表指标。

## 三次运行的统计量

每个方法和数据集共有 `n=3` 个独立系统运行样本。主表报告：

- 均值；
- 标准差；
- 样本方差 `s² = Σ(xᵢ - x̄)² / (n - 1)`。

每次运行内部的 3 次推理仅用于获得该次运行的中位数，不能将共 9 次内部推理当成
9 个独立样本。论文主表采用两位小数；高精度值和三次原始观测应保留用于复核。

原始 profile 位于 `results/efficiency/raw/`，两位小数论文表位于
`results/efficiency/combined_repeated_table_2dp.csv`，高精度合并统计位于
`results/efficiency/combined_repeated_statistics.csv`。本次实验日志统一归档在
`logs/OpenCLIP_LAION400M_ViTB16/<方法>/efficiency/`。
